# General Engineering Rules

- Use strict TypeScript once application code exists.
- Keep modules cohesive and dependencies justified.
- Make errors visible and actionable; do not swallow failures.
- Read environment values through validated configuration, never hard-coded secrets.
- Prefer clear names and small functions over comments that narrate obvious code.
- Update documentation when behavior or architecture changes.

Reason: predictable boundaries reduce accidental coupling and make AI-assisted changes reviewable.
