# Git and Documentation Rules

- Keep changes focused and commits understandable.
- Review findings come before summary and must include severity and evidence.
- Link significant implementation changes to specs and ADRs.
- Do not commit secrets, generated noise, or unrelated formatting churn.
- Record why durable choices were made, not every trivial implementation detail.
- A change is incomplete when its docs, tests, or knowledge are stale.

Reason: a long-lived project needs history that explains intent and scope.
